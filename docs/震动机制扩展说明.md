# 震动机制怎么加（扩展说明）

这份文档写给「以后要往这个 mod 里加新机制」的时候看。目标：**加一个新震动效果，
不需要动合成器的内部结构**，也不需要重新理解一遍整套代码。

---

## 1. 三层结构，改哪层要想清楚

```
游戏状态（asi_rdr2/）  →  合成器（proxy/gp_haptics.cpp）  →  输出通道（gp_wgi / gp_hid / XInput）
   读 native，写共享段        算出四个电机的值               把值写到硬件
```

| 你要加的机制 | 改哪一层 | 需要动 native 吗 |
|---|---|---|
| 由**已知状态**触发的（装弹、换枪、上马…） | 合成器 | 不用，状态里可能已经有 |
| 由**新的游戏信息**触发的（血量、体力、天气…） | 状态组件 + 合成器 | 要加 native |
| 由**手柄输入**触发的（按键、摇杆） | 合成器 | 不用 |
| 由**游戏震动波形**触发的 | 合成器 | 不用（但 RDR2 的波形没有事件信息，见第 5 节） |

---

## 2. 加一个「一次性反馈」—— 最省事的做法

所有「啪一下」的反馈都走同一个入口：`GpFireEffect()`。

**三步，以「装弹开始」为例**（这个已经做好了，可以照抄）：

**① 在 `proxy/gp_haptics.h` 的枚举里加一个 id**

```cpp
enum {
    GP_FX_DRAW   = 1,
    GP_FX_TICK   = 2,
    GP_FX_RELOAD = 3,   /* 开始装弹 */
    GP_FX_LT     = 4,
    GP_FX_YOURS  = 5,   /* 你新加的 */
};
```

**② 在 `GpHapticsSettings` 里加它自己的三个旋钮**

```cpp
float yourGain;      /* 0 = 关闭（默认就该是 0，别一上来就响） */
int   yourEnvMs;     /* 脉冲长度，10~500ms */
int   yourSide;      /* 0=右扳机 1=左扳机 2=两侧 */
```

顺手在三处补上：默认值（`GpDefaultHapticsSettings`）、夹紧范围
（`GpApplyHapticsSettings`）、配置读取（`gp_config.cpp` 的 `[Haptics]` 段）。
然后在 `dist/rdr2_haptics/gpxinput.ini` 里加同名键，并写清楚它默认关着。

**③ 在触发它的地方调一次**

```cpp
if (st->reloading && !cs->wasReloading) {           /* 上升沿，别每帧都调 */
    GpFireEffect(controller, GP_FX_RELOAD, g_s.reloadGain, g_s.reloadEnvMs, g_s.reloadSide);
}
cs->wasReloading = st->reloading != 0;
```

上升沿检测的字段加在 `CtrlState` 里（合成器的每控制器状态，见文件开头）。

**注意事项**

- `gain = 0` 就是「这个机制关着」—— 默认值必须是 0，不然玩家一升级就被新震动吓一跳。
- 只在**事件**上调用，不要每帧调（它不是设计给每帧用的）。
- 脉冲会自动和别的内容叠加，并受 `ShotReplaceGame` 一类的接管规则影响。

## 3. 加一个「持续效果」—— 参考瞄准与骑乘

持续效果（瞄准的微震、骑乘的蹄音）在 `GpTickHaptics()` 里按状态算，结构是：
**一个条件判断 + 往 add* 累加器里加值**。

```cpp
/* 例：受伤时持续抖动 */
if (g_s.injuryEnable && cs->stateValid && st_health_low) {
    float amp = g_s.injuryGain * 255.0f;
    addBodyL += amp;
    addBodyR += amp;
}
```

两条经验：

1. **要有起止判据**，别无条件输出。瞄准用「游戏说在瞄准」；骑乘用「在马上 +
   马速超过阈值」。判据差一点，玩家就会觉得「无缘无故在震」，那比不振更糟。
2. **周期型的东西（蹄音）只负责更新「拍点」，输出复用已有那段**。骑乘就是这么做的：
   状态版只算周期和幅度，输出那段按相位衰减，两版共用一份手感。

## 4. 加一个新 native

1. **先去官方 SDK 查签名**（`inc/natives.h`，从 dev-c.com 下 SDK）。参数个数和类型
   必须照抄 —— 少传一个参数不会报错，而是**时崩时好**：那一枪能打出去，下一枪
   访问违例。这事我们踩过两次（`GET_CURRENT_PED_WEAPON` 要 5 个参数、
   `GET_AMMO_IN_CLIP` 第 3 个是 `int*`）。
2. 哈希写进 `asi_rdr2/rdr2_natives.h`，并在 `asi_rdr2/natives_used.md` 登记签名与来源。
3. 状态字段加进 `include/gp_rdr2_state.h`，**同时改 `GPRDR2_VERSION`**（读侧会按版本
   拒绝不匹配的段，避免按错误布局读内存）。
4. 在 `Tick()` 里读它，写进快照。**每加一个 native 都要考虑它会不会失败**：
   `__try/__except` 兜住，并且失败时**不要**连累整帧（弹匣那个就是单独兜的）。

## 5. 单位、阈值与坑（都是实测踩出来的）

| 事项 | 结论 |
|---|---|
| 数值单位 | 累加器是 **0..255**（和硬件字节同量纲）。包络算出来是 0..1，**乘 255 再累加** —— 漏乘不会报错，只是手上完全没感觉 |
| 电机启动阈值 | 实测低于约 **8%（20/255）马达不转**。所以「设了 0.06 却完全没感觉」不是没生效，是没到阈值 |
| 扳机通道 | 只有 `Windows.Gaming.Input` 或 HID 报告能驱动。两条都不可用时，扳机内容会按 `TrigToBody` 折算到同侧体感 |
| 游戏本体震动 | RDR2 的震动是**一条连续渐变**（两路之和恒为 255），开枪/骑马/撞车在波形上完全分不出来。想「只认真正的开枪」必须读游戏状态 |
| 接管 vs 叠加 | 默认叠加（游戏原值 + 我们）。`ShotReplaceGame` 那种「脉冲期间让开游戏本体」的做法适合需要**定值手感**的效果 |
| 每帧的预算 | 合成器跑在实时路径上（125Hz，游戏线程也调）。里面不要做文件 IO、不要分配内存、不要加锁 |
| 状态新鲜度 | 写侧超过 1 秒没刷新，读侧一律视为「没有状态」并退回兜底判据。所以任何新机制都要想清楚：**状态掉线时它退化成什么** |

## 6. 现在能用的状态字段

`include/gp_rdr2_state.h` 里已经有：武器哈希、武器组（分档用）、弹匣总量、
距上次开枪、是否开枪、是否瞄准、是否装弹、是否持械、是否步行/骑马/车内、
是否菜单、马速。

**加机制之前先翻一眼这张表** —— 装弹反馈就是「表里已经有、接一行就好」的例子。
