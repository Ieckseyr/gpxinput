# RDR2 状态识别总表（我们到底能读到什么）

这份文档回答一个问题：**做任何震动机制之前，先查这张表——这个状态我们读不读得到、怎么读的、可不可靠。**

数据来源分四档：
- **N** = 直接读 native（ScriptHookRDR2，哈希已核对官方 SDK）
- **D** = 派生推断（由原始数据算出来，不经 native）
- **S** = 手柄侧（代理直接读手柄，不经游戏）
- **W** = 波形推断（分析游戏震动帧——RDR2 上基本不可用，见文末）

状态通过共享段 `Local\GpRdr2State_v1` 发布（**版本 5**），`.asi` 每游戏帧写一次，
代理侧 1 秒收不到刷新即视为失效并退回兜底参数。

## 一、位置与载具

| 字段 | 来源 | 说明 | 可靠性 |
|---|---|---|---|
| `onFoot` | N | 步行中 | ✅ |
| `onMount` | N | 在马/骑乘坐骑上 | ✅ |
| `inVehicle` | N | 在车/马车上 | ✅ |
| `mountHash` | N | 坐骑模型哈希 | ✅（未使用） |
| `horseSpeed` / `playerSpeed` | N | 实体速度（单位/秒） | ✅ |

## 二、马匹状态（骑乘反馈的依据）

| 字段 | 来源 | 说明 | 可靠性 |
|---|---|---|---|
| `horseGait` | **N** | **0=走步 1=小跑/坎特 2=疾驰 255=不在马上**（由 IS_PED_WALKING / RUNNING / SPRINTING 读出） | ✅ 蹄声拍数就按它给：走4/小跑2/坎特3/疾驰4 |
| `horseSpeed` | N | 蹄声周期与幅度随它插值 | ✅ |

## 三、武器与战斗

| 字段 | 来源 | 说明 | 可靠性 |
|---|---|---|---|
| `weaponHash` | N | 当前武器模型哈希（空手=0xA2719263） | ✅ |
| `weaponGroup` | N | 武器组（Pistol/Revolver/…） | ✅ |
| `armed` | D | 由 weaponHash 推导（IS_PED_ARMED 那个 native 实测恒 0，弃用） | ✅ |
| `shooting` | N | IS_PED_SHOOTING —— **开枪判据的主信号**（上升沿=一枪） | ✅ |
| `reloading` | N | 装弹中 | ✅ |
| `timeSinceShot` | N | 距上次开枪（「从未」时是 11 亿的哨兵值） | ⚠️ 仅显示用 |

## 四、移动与动作

| 字段 | 来源 | 说明 | 可靠性 |
|---|---|---|---|
| `playerGait` | N | 玩家步态 0=走 1=跑 2=冲刺 | ✅ |
| `jumping` | N | 跳跃中 | ✅ |
| `falling` | N | 坠落中 | ✅ |
| `climbing` | N | 攀爬中 | ✅ |
| `vaulting` | N | 翻越中 | ✅ |
| `swimming` | N | 游泳中 | ✅ |
| `prone` | N | 趴下 | ✅ |
| `deadOrDying` | N | 死亡/濒死 | ✅ |
| `grounded` | D | 站在地面上（以上动作都不成立） | ✅ |

## 五、界面与慢动作

| 字段 | 来源 | 说明 | 可靠性 |
|---|---|---|---|
| `menuActive` | D | 暂停菜单（IS_PAUSE_MENU_ACTIVE 恒 0 弃用；用 **IS_PLAYER_CONTROL_ON==0** 且排除下面这条） | ✅ |
| `uiOverlay` | D | **界面覆盖中：轮盘菜单 / 地图 / 物品栏**（控制权收走但非暂停菜单） | ⚠️ 推断：过场动画也命中 |
| `slowMotion` | D | **慢动作：timescale < 0.95** —— 死眼开启的典型特征；菜单背景慢动作也命中 | ⚠️ 推断：无法区分死眼与其它慢动作 |
| `timeScale` | D | 游戏时钟 ÷ 真实时钟（SDK 没有"读 timescale"的 native，只有 SET） | ✅ 量化本身可靠 |

> **死眼**：没有公开的 native。目前只能通过 `slowMotion`（timescale 掉下来）感知——
> 死眼开着的特征是「瞄准中 + timescale 掉到 0.6~0.8」。菜单也会压 timescale，
> 但死眼发生在瞄准中而菜单在非瞄准态，两个条件组合可以做到相当准确：
> `slowMotion && aiming` ≈ 死眼。

## 六、生命

| 字段 | 来源 | 说明 |
|---|---|---|
| `health` / `maxHealth` | N | 玩家生命值（受伤反馈的现成信号） |

## 七、手柄侧（S）—— 不经游戏，代理自己读

| 信号 | 说明 |
|---|---|
| LT / RT 按压量（0..255） | 125Hz 独立轮询，比游戏帧率高 |
| LT/RT 边沿 + 滞环 | 「按下 / 松开 / 扣到多深」 |

## 八、波形推断（W）—— RDR2 上基本不可用

实测 RDR2 的本体震动是**一条连续渐变**（两路之和恒 255，约 2 秒走完），没有瞬态。
开枪、骑马、撞车在波形上**分不出来**。所以凡「事件类」的识别一律走 native/派生，
波形判据只留作其它游戏的兜底（`ShotFromRumble=false`）。

## 九、想要但还没有的（等找到可靠来源再接）

| 想要的 | 现状 |
|---|---|
| **死眼的「开启/关闭」事件** | 只能从 timescale 推断，无 native |
| **轮盘菜单的打开/关闭事件** | `uiOverlay` 覆盖了它，但混有地图/物品栏 |
| 受击方向 / 受击部位 | `GET_PED_LAST_DAMAGE_BONE` 哈希已备（0xD75960F6BD9EA49C），未接 |
| 踢到/撞到东西 | `IS_ENTITY_TOUCHING_ENTITY`（0x9A2304A64C3C8423）、`HAS_ENTITY_COLLIDED_WITH_ANYTHING`（0xDF18751EC74F90FF）哈希已备，未接 |
| 地面材质（草地/石板/泥） | 无公开 native（`GET_GROUND_Z` 只给高度） |

哈希来源：官方 SDK `inc/natives.h`（详见 `natives_used.md`）。新增 native 前先查
SDK 签名 —— 少传参数会**时崩时不崩**，是本项目踩过两次的坑。
